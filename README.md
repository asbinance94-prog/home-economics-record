# السجل الإنجازي — قسم الاقتصاد المنزلي

مدرسة الموهوبين المتوسطة بنات (١) — العام الدراسي 2026/2027.
يُقدَّم للموجّهة الفنية خالدة.

**رابط المعلمات:** https://asbinance94-prog.github.io/home-economics-record/

**رابط الموجّهة (قراءة فقط):** https://asbinance94-prog.github.io/home-economics-record/?view=supervisor

> الواجهة جاهزة، لكن القراءة والحفظ لن يعملا حتى تنشرين Google Apps Script وتضعين رابط `/exec` في `config.js`. القيمة الحالية هي `PASTE_API_URL_HERE`. عند عدم الاتصال، تظهر رسالة واضحة وشرطة بدل الأعداد؛ لا تُعرض بيانات محلية أو نجاح وهمي.

## ١. شلون أنشر Google Apps Script؟

1. افتحي [Google Apps Script](https://script.google.com/) واضغطي **مشروع جديد**.
2. انسخي محتوى [backend/Code.gs](backend/Code.gs) كاملًا والصقيه مكان محتوى `Code.gs` في المشروع. احفظي. لا تحتاجين رفع `Index.html` إلى Apps Script.
3. افتحي **إعدادات المشروع ⚙️ → خصائص النص البرمجي (Script Properties) → إضافة خاصية**.
4. اكتبي الاسم `DEPARTMENT_SECRET`، وضعي قيمة سرية قوية للقسم من 16 حرفًا على الأقل، وبحد أقصى 256 حرفًا. احفظيها وشاركيها مع أعضاء القسم فقط. لا تضعي الرمز في GitHub أو `config.js` أو رابط أو QR.
5. ارجعي للمحرر، اختاري الدالة `setupBackend` من القائمة العلوية، ثم اضغطي **تشغيل**. وافقي على صلاحيات Google للجدول وDrive بعد مراجعتها. تُنشئ هذه الخطوة الجدول ومجلد الشواهد وتحفظ معرّفيهما آليًا.
6. اضغطي **نشر → عملية نشر جديدة → تطبيق ويب (Web app)**.
7. اختاري **التنفيذ بصفتي: أنا (Me)**، و**من لديه حق الوصول: أي شخص (Anyone)**. ليس «أي شخص لديه حساب Google».
8. اضغطي **نشر**، ثم انسخي رابط تطبيق الويب الذي ينتهي بـ **`/exec`**، وليس `/dev`.
9. في GitHub افتحي [config.js](config.js)، واضغطي القلم. استبدلي `PASTE_API_URL_HERE` بالرابط، داخل علامتي التنصيص:

```js
window.RECORD_CONFIG = Object.freeze({
  API_URL: 'https://script.google.com/macros/s/معرف_النشر/exec'
});
```

10. اضغطي **Commit changes** على الفرع `main` وانتظري نجاح النشر في **Actions**. أعيدي فتح الموقع.

إذا لم يظهر خيار **Anyone**، فقد تمنعه سياسة حساب المدرسة؛ يلزم حساب يسمح بهذا النوع من النشر أو موافقة مسؤول الحساب. لا يمكن ضمان عمل `fetch` عبر صفحة تسجيل دخول Google.

### لو عندك جدول أو مجلد سابق

الأفضل تعديل **نفس مشروع Apps Script القديم** مع إبقاء `SHEET_ID` و`FOLDER_ID` في Script Properties. عند استخدام مشروع جديد، انسخي هذين المعرّفين إليه قبل تشغيل `setupBackend` لكي يستمر استخدام بياناتك السابقة. المعرّف هو الجزء بعد `/d/` في رابط Sheets، وبعد `/folders/` في رابط مجلد Drive. لا تغيّري أسماء أعمدة ورقة `الإنجازات` أو ترتيبها.

البرنامج لا يستبدل الجدول بجدول فارغ إذا تعذّر فتح معرّفه؛ يعرض خطأ لتصحيح الوصول. وبحسب توضيحك، لم تُنقل بيانات فعلية من Google خلال تجهيز هذا المشروع.

### عند تعديل Code.gs لاحقًا

احفظي التعديل، ثم **نشر → إدارة عمليات النشر → القلم → الإصدار: إصدار جديد → نشر**. حافظي على نفس عملية النشر ليستمر رابط `/exec` نفسه. تعديل الكود دون نشر إصدار جديد لا يحدّث API المنشور.

## ٢. شلون أغيّر الرمز السري؟

من Apps Script: **إعدادات المشروع → Script Properties → DEPARTMENT_SECRET**، عدّلي القيمة واحفظي. يبدأ العمل بالرمز الجديد فورًا دون تعديل الواجهة أو إعادة نشرها.

تُدخل المعلمة الرمز عند الحفظ أو الحذف، وهو لا يُحفظ في localStorage أو ملفات الواجهة. الرمز الصحيح محفوظ في Script Properties؛ يُرسل الرمز المُدخل داخل جسم طلب HTTPS للتحقق منه في الخادم، ولا يُرسل ضمن الرابط. يستخدم القسم رمزًا مشتركًا، وليس حسابًا مستقلًا لكل معلمة.

## ٣. استخدام الموقع

- **إضافة إنجاز:** اختاري العضوة والتصنيف، واكتبي العنوان والتاريخ والوصف. ارفعي الشاهد أو أضيفي رابطًا، وأدخلي الرمز، ثم احفظي.
- **حذف:** اضغطي حذف، راجعي عنوان الإنجاز، وأدخلي الرمز. تُحذف سطر الإنجاز من Sheets؛ يبقى الملف في Drive لحفظ الأرشيف.
- **الفلاتر:** اضغطي بطاقة العضوة أو التصنيف، أو استخدمي القائمتين. الضغط على البطاقة المحددة مرة ثانية يلغي اختيارها.
- **الموجّهة:** رابط `?view=supervisor` يعرض السجل والفلاتر والطباعة، دون أزرار إضافة أو حذف أو نموذج إدخال. إزالة هذا الجزء من الرابط لا تمنح صلاحية تعديل بدون الرمز الصحيح.
- **PDF:** اختاري الفلتر المطلوب ثم «طباعة / PDF». اختاري **حفظ كـ PDF** وحجم **A4**، وأوقفي رؤوس وتذييلات المتصفح. تُطبع الإنجازات الظاهرة حسب الفلتر، كما في الأصل، وتظهر العضوة والتصنيف المختاران على النسخة المطبوعة. إحصائيات القسم إجمالية كما في النسخة الأصلية.
- **الشواهد:** الحد 20MB لكل ملف؛ الصور JPG/PNG/WebP/GIF، وPDF، والفيديو MP4/WebM/MOV. للملفات الأكبر استخدمي حقل الرابط.
- إذا انقطع الاتصال أثناء الحفظ، لا يُعرض نجاح دون تأكيد. حدّثي القائمة أولًا؛ قد يكون الطلب وصل للخادم. إعادة محاولة نفس طلب الإضافة من النموذج نفسه تستخدم معرّفًا ثابتًا لمنع التكرار.

### إتاحة القراءة

الموقع والقراءة عبر API متاحان لمن يملك الرابط، وقد يمكن الوصول إليهما خارج القسم. وضع الموجّهة ليس تسجيل دخول خاصًا. الشواهد تُشارك في Drive بصلاحية **أي شخص لديه الرابط: مشاهدة**، مثل الكود الأصلي. لا ترفعي مستندات أو صور طالبات تحتاج حماية خاصة بهذه الآلية. الإضافة والحذف ورفع الملفات تتطلب الرمز في الخادم.

## ٤. شلون أسوي QR للرابطين؟

1. افتحي رابط المعلمات في Chrome.
2. من قائمة Chrome اختاري **Cast, save and share → Create QR code** (أو «إنشاء رمز QR» ضمن المشاركة)، ثم نزّلي الصورة.
3. كرري الخطوتين مع رابط الموجّهة، وتأكدي أنه ينتهي بـ `?view=supervisor`.
4. سمّي الصورتين «رابط المعلمات» و«رابط الموجّهة»، وجرّبي المسح بالجوال قبل الطباعة. لا تضعي الرمز السري داخل QR.

## ٥. شلون أربط domain خاص لاحقًا؟

1. بعد شراء النطاق، افتحي **Settings → Pages → Custom domain** في المستودع، واكتبي النطاق واحفظي.
2. لنطاق مثل `www.example.com` أضيفي لدى مزوّد النطاق سجل **CNAME** باسم `www` وقيمته `asbinance94-prog.github.io`، بدون اسم المستودع.
3. للنطاق الرئيسي مثل `example.com` اتبعي [قيم DNS الحالية في دليل GitHub](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site).
4. بعد اكتمال فحص DNS فعّلي **Enforce HTTPS**. يُفضّل توثيق ملكية النطاق من إعدادات الحساب.
5. رابط الموجّهة يصبح `https://www.example.com/?view=supervisor`. أعيدي توليد QR للرابطين الجديدين. لا يتغير رابط Apps Script في `config.js`.

## الملفات

- `index.html`: نفس هيكل الواجهة مع الاسم الرسمي والموجّهة.
- `style.css`: الألوان والتخطيط الأصليان؛ خط Noto Kufi Arabic للعناوين وNoto Naskh Arabic للنصوص حسب الطلب. الملف الأصلي المرفق كان يستخدم Tajawal.
- `app.js`: العرض والفلاتر واستدعاء API.
- `config.js`: رابط API فقط.
- `assets/images/logo.svg`: الشعار الأصلي المرفق دون تعديل.
- `backend/Code.gs`: كود الخادم؛ انسخيه إلى Apps Script.
- `.github/workflows/pages.yml`: ينشر الواجهة عند تعديل `main`. يرفع ملفات الواجهة فقط إلى Pages، ولا يرفع مجلد backend إلى ملفات الموقع.

من **Settings → Pages → Source** يجب اختيار **GitHub Actions**. مرجع: [GitHub Pages workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## ملاحظات API للمطوّر

- القراءة: `GET /exec?action=list` → `{ok:true, entries:[...]}`.
- الإضافة: `POST` بجسم `{action:"add", secret, requestId, entry, file}`؛ `requestId` هو UUID، و`file` اختياري بالشكل `{name,mimeType,data}` حيث data هي Base64 دون بادئة data URL. يتم رفع الملف وإضافة الإنجاز بطلب واحد.
- الحذف: `{action:"delete",secret,id}`. حذف معرّف غير موجود يعيد `deleted:false` دون تعديل بيانات أخرى.
- إرفاق أول شاهد لإنجاز قائم: `{action:"upload",secret,id,file}`. يرفض استبدال شاهد موجود.
- الأخطاء: `{ok:false,error:{code,message}}`. لا تدعم ContentService ضبط كود HTTP أو headers مخصصة، ولذلك يجب فحص `ok` حتى مع HTTP 200.
- CORS: يرسل المتصفح JSON داخل `text/plain;charset=UTF-8` دون Authorization header لتجنب طلب OPTIONS التمهيدي، مع `credentials:'omit'` واتباع إعادة التوجيه. لا يُستخدم `no-cors` لأنه يمنع قراءة النتيجة. هذه ليست معالجة OPTIONS مخصصة؛ Apps Script لا يوفرها. يلزم نشر Anyone والتحقق من الاستجابة الفعلية عبر المتصفح بعد وضع الرابط. مرجع: [ContentService](https://developers.google.com/apps-script/guides/content) و[TextOutput](https://developers.google.com/apps-script/reference/content/text-output).
- فُحصت حماية العمليات والتحقق من الحقول ورفع الملفات ومنع تكرار الطلب باختبارات محلية تحاكي خدمات Google. **لم تُختبر قراءة أو كتابة حقيقية إلى Google حتى الآن**؛ لم يتم نشر API بعد.
